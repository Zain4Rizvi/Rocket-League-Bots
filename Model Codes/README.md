# Rocket League Goal Prediction - Training System

Complete training pipeline for temporal goal prediction from video.

## 📋 Overview

This system trains a deep learning model to predict the probability of a goal occurring in the next 10 seconds of gameplay by analyzing video footage.

**Key Features:**
- ✅ Handles 2x speed video (30 FPS recorded, 2x gameplay speed)
- ✅ Predicts every 0.5 seconds of gameplay
- ✅ Full evaluation with distribution comparison
- ✅ Mixed precision training for GTX 1660
- ✅ Comprehensive metrics and visualizations

## 🏗️ Architecture

```
Input: Video (last 5 seconds = 150 frames at 30 FPS)
  ↓ (downsample to 10 FPS)
Input: 50 frames
  ↓
[EfficientNet-B0] → Spatial Features (per-frame)
  ↓
[LSTM] → Temporal Features (sequence modeling)
  ↓
[Dense Layers] → Threat Prediction [0, 1]
  ↓
Output: Threat probability at each frame
```

## 🚀 Quick Start

### 1. Prepare Your Data

Ensure each replay folder has:
- `*.mp4` - Video file (30 FPS, 2x speed)
- `goals.csv` - Goal frame annotations
- `distribution.npy` - Target threat distribution (generated by `create_threat_distribution.py`)

### 2. Configure Training

Edit `config.yaml`:

```yaml
data:
  replay_data_dir: "Replay Data"
  train_replays: 7
  test_replays: 1
  
training:
  epochs: 50
  batch_size: 4  # Adjust based on GPU memory
  learning_rate: 0.0001
```

### 3. Train Model

```bash
python train_model.py --config config.yaml
```

**Output:**
- Checkpoints saved to `outputs/rl_goal_prediction_TIMESTAMP/checkpoints/`
- TensorBoard logs in `outputs/rl_goal_prediction_TIMESTAMP/tensorboard/`
- Training history in `outputs/rl_goal_prediction_TIMESTAMP/training_history.json`

**Monitor training:**
```bash
tensorboard --logdir outputs/rl_goal_prediction_TIMESTAMP/tensorboard
```

### 4. Evaluate Model

```bash
python evaluate_model.py \
  --checkpoint outputs/rl_goal_prediction_TIMESTAMP/checkpoints/best_model.pt \
  --config config.yaml
```

**Output:**
- Full predictions for each video: `evaluation_results/Replay_XXX_predictions.npy`
- Comparison plots: `evaluation_results/Replay_XXX_comparison.png`
- Summary statistics: `evaluation_results/evaluation_results.json`

## 📊 Understanding the Outputs

### Training Metrics

**During Training:**
- `Train Loss`: Combined loss (main + smoothness)
- `Val Loss`: Validation loss
- `Val AP`: Average Precision (primary metric, higher is better)
- `Val MAE`: Mean Absolute Error (lower is better)
- `Early Detection Rate`: % of goals detected 2s early
- `False Alarm Rate`: False alarms per minute

**Best model selected by highest Average Precision.**

### Evaluation Metrics

**Per-Video:**
- `MAE`: Mean Absolute Error between predicted and target distribution
- `RMSE`: Root Mean Squared Error
- `Correlation`: Pearson correlation coefficient
- `Peak Alignment Error`: Average frame difference between prediction and target peaks
- `Shape Similarity`: Normalized cross-correlation (0-1, higher is better)

**Aggregate:**
- Mean and standard deviation across all videos
- Separate statistics for train and test sets

### Visualization

Each evaluation generates 3 plots:

1. **Overlay Plot**: Predicted vs Target distribution over time
2. **Error Plot**: Frame-by-frame prediction error
3. **Scatter Plot**: Target vs Predicted threat (diagonal = perfect prediction)

## ⚙️ Hyperparameter Tuning Guide

### Training Parameters

**Batch Size** (`training.batch_size`)
- Default: 4
- GTX 1660: 4-8 (depending on resolution)
- More VRAM: Increase for faster training
- Less VRAM: Decrease to 2

**Learning Rate** (`training.learning_rate`)
- Default: 0.0001
- Too high: Training unstable, loss oscillates
- Too low: Training too slow, may get stuck
- Try: [0.00001, 0.00005, 0.0001, 0.0005]

**Loss Function** (`training.loss.type`)
- `focal`: Best for class imbalance (recommended)
- `weighted_bce`: Alternative for imbalance
- `bce`: Standard binary cross-entropy
- `mse`: Regression loss

### Model Parameters

**Backbone** (`model.spatial_encoder.backbone`)
- `efficientnet_b0`: Fast, good accuracy (recommended)
- `resnet18`: Faster, slightly less accurate
- `resnet34`: More accurate, slower

**LSTM Hidden Size** (`model.temporal_encoder.hidden_size`)
- Default: 256
- Smaller (128): Faster, less capacity
- Larger (512): More capacity, slower

**Temporal Encoder** (`model.temporal_encoder.type`)
- `lstm`: Good for sequential modeling (recommended)
- `gru`: Slightly faster than LSTM
- `transformer`: More powerful, needs more data

### Data Parameters

**Lookback Window** (`data.lookback_seconds_gameplay`)
- Default: 10 seconds gameplay (5 seconds video)
- Shorter (5s): Less context, faster training
- Longer (15s): More context, slower training

**Frame Downsampling** (`data.target_fps`)
- Default: 10 FPS (from 30 FPS)
- Higher (15 FPS): More temporal resolution, slower
- Lower (5 FPS): Faster, might miss details

**Prediction Interval** (`data.prediction_interval_frames`)
- Default: Every 8 frames (0.5s gameplay)
- More frequent (4 frames): More samples, slower
- Less frequent (16 frames): Fewer samples, faster

## 🐛 Troubleshooting

### Out of Memory (OOM)

**Symptoms**: CUDA out of memory error

**Solutions:**
1. Reduce `batch_size` (try 2 or 1)
2. Reduce `target_fps` (try 5 FPS instead of 10)
3. Reduce `lookback_frames` (try 3 seconds instead of 5)
4. Use smaller backbone (`resnet18` instead of `efficientnet_b0`)

### Loss Not Decreasing

**Possible causes:**
1. Learning rate too high → Try 0.00001
2. Bad initialization → Restart training
3. Not enough data → Use more data augmentation
4. Task too hard → Check if target distributions are reasonable

### Model Predicts All Zeros or All Ones

**Symptoms**: Model outputs constant value

**Solutions:**
1. Check class imbalance → Use `focal` loss
2. Reduce learning rate → Try 0.00005
3. Check target distributions → Ensure variety
4. Add more regularization → Increase dropout

### Training Too Slow

**Solutions:**
1. Reduce `num_workers` if CPU bottleneck
2. Use mixed precision (already enabled)
3. Reduce `target_fps` to 5
4. Increase `prediction_interval_frames` to 16
